# Shipping

**Everyone here is shipping, how are they doing that ? Is this wizardry or smtg ?**

If you are lost, and don't know how to ship for this event, don't worry because we cooked you this little guide !

### 1. What is a ship (yk, the basics)

At Hack Club, ships are the reason to run YSWS (and to give you cool rewards).

Basically, they're the fruit of your work. They must be open sourced, trough sites like [Github](https://github.com/), [Gitlab](https://gitlab.com), or our very own [Forgejo](https://git.hackclub.app/) (yup, we do have that. we have everything.). If it's a software project, it should be runnable on people's computer.

After shipping, reviewers will check your project, so it should work for them! If it doesn't, you will probably be asked to reship the project.

### 2. Get your project ready

Before shipping, make sure to test everything; you don't want your main feature to be unusable, nor any of the other features you bragged about in the README.

Yup, the README. That may look boring, but look at me, I'm basically writing a giant README while creating these docs. It's not that horrible, trust me.

In a README, you don't want to have a big wall of text. Here is some advices:
- **Use some Markdown syntax:** Plain text is boring. Add some titles, bold, notes... Github even has [docs about this](https://docs.github.com/en/get-started/writing-on-github/getting-started-with-writing-and-formatting-on-github/basic-writing-and-formatting-syntax) !
- **Add images:** I can read about your amazing features, but seeing the program in action is waaaay better, trust me. [Here is how to do it on Github!](https://docs.github.com/en/get-started/writing-on-github/getting-started-with-writing-and-formatting-on-github/basic-writing-and-formatting-syntax#images)
- **Talk about your project:** If I read the README, it's because I want to know more. Tell me the features, the limitations, or even complain about some badly documented API that your whole project depends on! Also, remember that it's a presentation, not a list of names of the things that you used (even if it's nice to have Credits)!

If you want more advices, check out [Stardance's guide about that](https://stardance.hackclub.com/resources/great_readme)! It's a really great ressources to make a cool README.

When you finished the README, make sure your project is easily reviewable. If it's a python library, publish it on PyPi! If it's a website, host it on Vercel!

Test a last time (we're never sure), and then you're good to go!

### 3. Ship

When shipping, you will need to enter your project's infos and proofs for the constraints.

Then, you will need to wait for a reviewer to take your project in charge! This can take a long time.

After reviewing, your reviewer will approve or disapprove your project. They may request for changes; you will need to fix them before reshipping.

After that, you're done ! You can start shopping :)
